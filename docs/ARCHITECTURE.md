## Главный принцип

**Сервер на Render ничего не хранит у себя.** Его диск стирается при каждом перезапуске, деплое и засыпании. Всё, что нельзя потерять, лежит снаружи:

| Что | Где | Почему |
|---|---|---|
| Переписки, сообщения, настройки, задачи, прогресс, журнал событий | Neon PostgreSQL | Нужны транзакции и быстрые запросы |
| Файлы проектов, ассеты, zip-архивы | Cloudflare R2 | Большие бинарные данные |
| Список файлов (путь, размер, sha256) | Neon (индекс) | Быстрый листинг; при потере восстанавливается из R2 (`/api/reindex`) |
| Код | GitHub | История изменений |
| Модели | GPU-узел | Вычисления; состояния не хранит |

## Что происходит при сбоях

| Событие | Поведение |
|---|---|
| Перезапуск или деплой Render | Новый процесс подключается к Neon. Задачи в статусе «выполняется» с истёкшей арендой (lease) возвращаются в очередь и продолжаются **с последнего сохранённого шага**. Сообщения со статусом «идёт ответ» помечаются «прервано», а не пропадают. |
| Засыпание Render (15 минут без запросов) | То же, что при перезапуске. Первый запрос будит сервис примерно за минуту. |
| GPU-узел выключен | Роутер переходит на следующий провайдер в цепочке (например, облачный API) или на заглушку. Фоновые задачи **не падают**: откладываются с интервалом и продолжаются, когда GPU вернётся. Попытки при этом не расходуются. |
| Neon «уснул» (5 минут простоя) | Первое подключение занимает доли секунды, соединение переоткрывается автоматически, перед повторным использованием старого соединения идёт проверка. |
| R2 недоступен | Запись и чтение файлов возвращают понятную ошибку 503; остальное API работает. |
| Потеряна БД | Файлы целы в R2, индекс восстанавливается `reindex`. Переписки восстанавливаются из `/api/export` (резервная копия). |
| Закрыта вкладка в середине ответа | Частичный ответ сохранён со статусом «прервано». |

## Как устроены задачи

Задача — строка в таблице `tasks` со статусом `queued → running → done / failed / cancelled`.

1. Воркер (поток внутри сервиса) забирает задачу атомарным `UPDATE … WHERE status='queued'` и ставит **аренду** на 60 секунд, продлевая её по ходу работы.
2. После каждого шага агент сохраняет `state` (план, результаты шагов) в БД.
3. Если процесс умер, аренда истекает, и любой новый процесс возвращает задачу в очередь. Агент читает `state` и пропускает уже сделанные шаги.
4. Если все модели недоступны, задача получает `run_after` на 30–120 секунд вперёд и ждёт; счётчик попыток не растёт.
5. После `TASK_MAX_ATTEMPTS` реальных ошибок задача получает статус `failed` с текстом ошибки.

## Агент кода («тело»)
Задача типа `code` (`backend/code_agent.py`, `backend/github_client.py`): модель отвечает JSON-вызовами инструментов, сервер выполняет их над снимком репозитория, правки копятся в состоянии задачи (Neon) и уходят одним коммитом в ветку `gdai/*` с pull request. Подробно и простыми словами: [BODY.md](BODY.md).

## Провайдеры моделей

`config/providers.json` описывает провайдеров **без секретов**: только имена переменных окружения. Типы: `openai_compatible` (vLLM, Ollama, llama.cpp, LM Studio, OpenRouter, Groq, OpenAI), `anthropic`, `stub`. Провайдер считается настроенным, когда заданы его переменные окружения. Роутер идёт по цепочке `default_chain`, пропускает недоступных (проверка здоровья с кратким кэшем и «паузой» после сбоя), клиент может выбрать провайдера и модель в запросе. Чтобы добавить новую модель или GPU-узел, достаточно запись в JSON и переменные окружения.

## Безопасность

- Публичный сервер без защиты позволил бы любому тратить твой GPU и писать в R2, поэтому все `/api/*`, кроме `/api/health`, требуют заголовок `Authorization: Bearer <API_TOKEN>`. Без `API_TOKEN` сервер отвечает 503 (кроме явного `ALLOW_NO_AUTH=1` для локальной разработки).
- Секреты (строка Neon, ключи R2, токены GPU) живут только в переменных окружения Render. В репозитории их нет.
- CORS разрешён только для адресов из `CORS_ORIGINS`.
- Файлы: проверка пути (без `..`), список разрешённых расширений, лимит размера.
- Ключи не принимаются в API настроек.

## Лимиты бесплатных тарифов (проверено 13.11.2026)

- **Render free**: засыпает через 15 минут без трафика, холодный старт около минуты, 750 часов в месяц на воркспейс, диск временный, один экземпляр, фоновые воркеры как отдельный бесплатный тип не предусмотрены (поэтому воркер работает внутри веб-сервиса). Источник: [render.com/docs/free](https://render.com/docs/free).
- **Neon free**: 1 ГБ на проект, 100 CU-часов в месяц, остановка вычислений после 5 минут простоя, пулер PgBouncer. Источник: [neon.com](https://neon.com/faqs/managed-postgres-databases-free-tier).
- **Cloudflare R2**: бесплатно 10 ГБ-мес хранения, 1 млн операций класса A, 10 млн класса B, трафик наружу бесплатный. Требуется ли привязка карты для включения R2, в документации по тарифам не сказано: смотри при регистрации. Источник: [developers.cloudflare.com/r2/pricing](https://developers.cloudflare.com/r2/pricing).

**Чего бесплатные тарифы не гарантируют:** пока Render спит, фоновые задачи стоят (продолжатся при пробуждении, ничего не теряется). Бесплатного GPU «навсегда» нет: временные сессии Colab/Kaggle или собственный компьютер подойдут, но будут отключаться, ради этого и сделаны очередь и запасные провайдеры.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `API_TOKEN` | Секрет для доступа к API (обязательно) |
| `DATABASE_URL` | Строка подключения Neon (`postgresql://…`, лучше pooled) |
| `CORS_ORIGINS` | Через запятую, например `https://имя.github.io` |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | Доступ к R2 |
| `GPU_BASE_URL`, `GPU_API_KEY`, `GPU_MODEL` | GPU-узел (OpenAI-совместимый адрес) |
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | Резервный облачный провайдер (необязательно) |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | Claude (необязательно) |
| `GITHUB_TOKEN`, `GITHUB_REPOS` | Токен для агента кода (Contents + Pull requests, только нужный репозиторий) и список разрешённых репозиториев, см. [GITHUB.md](GITHUB.md) |
| `TASK_MAX_ATTEMPTS`, `LEASE_SECONDS`, `MAX_FILE_MB` | Тонкая настройка (есть значения по умолчанию) |

Без `DATABASE_URL` и R2 сервер работает на локальных SQLite и папке `data/`: удобно для разработки, но **на Render эти данные пропадут**. Эндпоинт `/api/health` честно показывает `persistent: false`.
