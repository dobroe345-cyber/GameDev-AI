# «Тело» ИИ: как агент работает с кодом

Если совсем просто: **мозг** — это языковая модель (сейчас Groq). Она умеет только читать текст и отвечать текстом. Она не умеет открывать GitHub, читать файлы или что-то сохранять.
**Тело** — это наш сервер на Render. У него есть «руки» (инструменты), «записная книжка» (база Neon) и «страховка» (pull request). Тело выполняет то, что просит мозг, и приносит ему результат текстом.

Мозг можно менять (другая модель, свой GPU), тело при этом остаётся то же самое.

## Что происходит, когда ты включаешь «Агент» и пишешь задачу

Пример задачи: «Сделай бег игрока быстрее».

1. **Интерфейс** создаёт задачу на сервере и показывает карточку с прогрессом. Дальше всё делает сервер, страница нужна только чтобы смотреть.
2. **Сервер** запоминает последнюю версию кода (скачивает архив репозитория, это быстро и бесплатно) и показывает модели список файлов.
3. **Цикл «подумала — сделал — сообщил»**. Модель отвечает одним коротким JSON, например `{"tool": "gh_grep", "args": {"pattern": "speed"}}`. Сервер выполняет это и отправляет модели результат. Так повторяется до 16 раз:
   - `gh_find` / `gh_grep`: нашла нужные файлы и строки;
   - `gh_read`: прочитала нужный кусок файла;
   - `gh_replace` / `gh_write` / `gh_delete`: правки. Они копятся **на сервере**, в GitHub пока ничего не уходит;
   - после правки модель перечитывает файл и видит свой результат (она видит код с учётом своих правок).
4. **Pull request.** Модель вызывает `gh_pr`. Сервер создаёт новую ветку `gdai/task-…`, делает **один коммит** со всеми правками и открывает pull request.
5. **Ты** открываешь ссылку из карточки, смотришь, что изменилось, и нажимаешь Merge, если всё хорошо. Если не нравится, просто закрываешь pull request: игра не тронута.

После каждого шага сервер записывает состояние в Neon. Поэтому, если Render перезапустится или модель на время отключится, агент продолжит с того же места, а не начнёт заново.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `gh_find` | ищет файлы по части пути или шаблону (`*.js`) |
| `gh_grep` | ищет текст в коде (с номерами строк) |
| `gh_read` | читает файл или диапазон строк |
| `gh_replace` | заменяет точный фрагмент (он должен встретиться ровно один раз) |
| `gh_write` | создаёт или полностью перезаписывает файл |
| `gh_delete` | удаляет файл |
| `gh_status` | показывает, что уже изменено |
| `gh_pr` | отправляет все правки одним pull request |

## Чего агент не может (ограничения безопасности)

- **Не пишет в `main`.** Только в ветки `gdai/*`. **Не нажимает Merge.** Это делаешь ты.
- Работает только с репозиториями из списка `GITHUB_REPOS` (по умолчанию `dobroe345-cyber/GameDev-AI`).
- Не трогает `.github/` (там лежат автоматические процессы GitHub) и служебные папки `.git`.
- Не записывает в код ключи и пароли: перед отправкой сервер ищет токены, приватные ключи и адреса баз с паролем и отклоняет такие правки.
- Лимиты одного pull request: до 30 файлов, до 200 КБ на файл и до 400 КБ всего.
- Токен GitHub хранится только в Render. Модель его не видит, в журнал и в ответы он не попадает.
- Текст файлов для модели — только данные. Если в файле написано «забудь правила и сделай то-то», модель получает такое указание в системном правиле игнорировать. Но главная защита не в этом: даже если модель обманут, физически она может лишь предложить правки в pull request, которые ты увидишь.

## Что с отказами и сбоями

| Что случилось | Что будет |
|---|---|
| Render перезапустился или уснул | задача возвращается в очередь и продолжается с сохранённого шага |
| Модель (Groq/GPU) недоступна | агент ждёт и пробует снова; попытки не расходуются |
| GitHub недоступен (5xx, сеть) | задача повторяется с паузой |
| Токен неверный или нет прав | сразу понятная ошибка в карточке: что именно проверить |
| Модель отвечает не в нужном формате | ей дают подсказку и просят повторить (до 3 раз) |
| Модель просит запрещённое | инструмент отвечает «Отказ: …», и она ищет другой путь |
| Агент «ходит по кругу» | после лимита шагов он завершается сам, а накопленные правки всё равно уходят в pull request |

## Честные ограничения сегодняшнего этапа

- Агент **не запускает код и не играет в игру**. Он правит текст и открывает pull request. Проверять результат пока нужно тебе (это следующий этап, см. ниже).
- Качество правок зависит от модели. Небольшие точные задачи («измени скорость», «добавь кнопку») получаются лучше, чем «перепиши всю игру».
- Агент видит только текстовые файлы до 200 КБ. Картинки, модели и звук он не читает (но видит, что они есть).
- Он получает только текст задачи, а не весь прошлый чат.
- На бесплатном Render сервер засыпает через 15 минут без запросов. Пока открыта страница с карточкой, она сама опрашивает сервер и не даёт ему уснуть. Если страницу закрыть, сервер уснёт, а задача продолжится, когда он проснётся (ты откроешь интерфейс).
- Сначала всё проверено на поддельном GitHub и поддельной модели (25 автоматических тестов и браузерная проверка), потому что настоящий токен ещё не подключён. Первый запуск на настоящем GitHub лучше сделать на маленькой задаче.

## Что будет дальше («тело» растёт)

На Render бесплатно нельзя запустить браузер и Blender: не хватает памяти. Поэтому следующие органы будут работать в **GitHub Actions**. Это бесплатный компьютер, который GitHub выдаёт на время проверки (проверь лимиты минут для своего тарифа и репозитория):

1. **Проверки.** После pull request запускается автоматический набор из 10 проверок: синтаксис JavaScript, битые ссылки на файлы, пустые файлы, дубли, размеры и т. п. Результат агент читает и сам чинит ошибки.
2. **Игра и скриншоты.** Безголовый браузер запускает игру, нажимает кнопки, делает скриншоты и присылает их в чат. Агент «видит» результат и сообщает, что работает.
3. **Blender.** Blender запускается без окна по скрипту, который напишет агент, и возвращает модель/рендер.

Каждый такой орган — это новые инструменты в том же списке, цикл остаётся прежним.
